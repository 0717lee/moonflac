# Independent validation

`scripts/validate.py` calls **libFLAC**, through Python ctypes, solely as an
independent validation oracle. The MoonFLAC library has no dependency on it.
No expected sample is generated by the MoonFLAC decoder.

On Windows, run `pwsh -File scripts/prepare-validation.ps1`. This downloads the
official Xiph FLAC 1.5.0 Windows release and the public CELLAR corpus into ignored
`validation/cache/`, prints their identities, and generates 245 independent cases.
On other platforms install libFLAC, clone the corpus to the same location, and run
`python scripts/validate.py generate --libflac /path/to/libFLAC.so`.

The generated cases cover every combination of 4–32 bits and 1–8 channels,
signed extrema, zero, negative one, tonal and random data, rates up to 1048575 Hz,
blocks up to 65535 samples, final short blocks, and Ogg mapping. libFLAC encodes
the integer source, then its decoder verifies that exact source before the
reference PCM is saved. The manifest records format, sample count and SHA-256.
This does not imply exhaustive coverage of every predictor/Rice coding choice;
the public corpus supplies deliberately unusual codings.

After building the native CLI:

```sh
python scripts/validate.py compare --cli /absolute/path/to/moonflac --corpus generated
python scripts/validate.py compare --cli /absolute/path/to/moonflac --corpus subset
```

The corpus's combined metadata file55 needs a larger explicit resource limit:
append `--max-buffer 134217728` to the comparator. Its metadata exceeds the
default32MiB compressed-buffer limit. This is a configurable resource boundary,
not an invalid-format classification.

The CLI contract is `decode INPUT OUTPUT --raw`: interleaved signed integers,
little-endian, `ceil(bits/8)` bytes per sample, sign-extended unused upper bits.
Each output is compared byte-for-byte with libFLAC's integer callback samples.
Results are recorded incrementally in ignored `validation/results/oracle.json`.
Nonzero return means at least one comparison or reference decode failed. A
reference failure is never silently counted as a MoonFLAC pass.

## Corpus interpretation

Read the upstream top-level and per-group `README.txt` before interpreting results.
`subset` contains valid files, including legacy variable blocking (#27), unusual
metadata (#45–59), 64-bit predictor stress (#61–63), and zero-width escaped Rice
residuals (#64). The spoken multichannel files #38–43 provide real-audio content
and channel ordering evidence.

`uncommon` also contains valid streams: #01–04 change audio properties, #05–09
exercise 32-bit, high-rate, 15-bit, maximum-block and Rice partition-order limits;
#10–11 simulate raw multicast FLAC, with no metadata and possibly an unsynchronized
prefix. Such streams need the raw-frame API rather than strict file decoding.
The fixed-format raw output comparator intentionally raises on changing properties.
Use the independent per-frame comparison for the entire uncommon group:

```sh
moon build --target native validation/runner
python scripts/validate.py frames --cli _build/native/debug/build/validation/runner/runner.exe --corpus uncommon
```

It compares frame block size, rate, bit depth, channels and every signed32 PCM
integer. Raw stream11 explicitly expects libFLAC's LOST_SYNC event; all other
reference errors remain failures. MoonFLAC's discarded bytes are recorded.

`scripts/generate-golden.py` produces portable, committed MoonBit byte literals
from independent references, including first frames extracted from public corpus
12/16/31/61/64 with recomputed STREAMINFO totals and independent-PCM MD5. These
14 fixtures run without external tools on native/JS/wasm-gc. Their provenance and
SHA-256 values are in `validation/golden/sources.json`.

```sh
moon test --target js validation/golden
moon test --target wasm-gc validation/golden
python scripts/check-faulty.py --cli /absolute/path/to/moonflac
```

`faulty` contains malformed metadata, size mismatches, invalid blocks and corruption.
Its stated requirement is no crash or hang; this project additionally requires
explicit error/diagnostic and no unchecked incorrect PCM. Metadata/frame property
mismatch is distinguishable from valid property changes and should be reported
according to the API's documented policy.
